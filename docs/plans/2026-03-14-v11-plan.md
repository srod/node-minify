# v11 Plan: Cleanup Major with Support Tiers and Java Simplification

## Summary

v11 should remain a focused `@node-minify` cleanup release under the existing scope, but it should also use `yui` removal to simplify the remaining Java-related architecture.

The release should:

- remove clearly obsolete compressors
- introduce explicit compressor support tiers
- add one migration-focused DX feature: `node-minify doctor`
- replace the custom Java wrapper path used by `google-closure-compiler` so Java-specific repo plumbing is reduced even if Java may still exist as an upstream fallback in some environments

## Key Changes

### Public package and type changes

- Remove these packages from v11:
  - `@node-minify/babel-minify`
  - `@node-minify/uglify-es`
  - `@node-minify/yui`
  - `@node-minify/sqwish`
  - `@node-minify/crass`
- Remove deprecated type aliases from `@node-minify/types`:
  - `CompressorReturnType`
  - `MinifyOptions`

### Compressor support tiers

- `Legacy` in v11:
  - `jsonminify`
- `Supported but not recommended`:
  - `clean-css`
  - `csso`
  - `uglify-js`
  - `google-closure-compiler`
  - `imagemin`
  - `html-minifier`
- `Recommended`:
  - JS: `terser`, `oxc`, `swc`, `esbuild`
  - CSS: `lightningcss`, then `cssnano` / `clean-css`
  - HTML: `minify-html`
  - Images: `sharp`, `svgo`

### Java and GCC cleanup

- Remove all YUI-specific Java logic:
  - delete the YUI package and bundled jar path
  - remove YUI-only docs, tests, CLI help entries, action guidance, and type requirements
  - remove YUI migration references outside the dedicated migration guide
- Refactor `@node-minify/google-closure-compiler` to stop depending on:
  - `@node-minify/run`
  - `google-closure-compiler-java`
- Switch GCC to the maintained `google-closure-compiler` npm package backend
- Remove the standalone `@node-minify/run` package if it has no remaining consumers after the GCC refactor
- Update docs to describe GCC as a supported but less-preferred option, without presenting repo-owned Java execution as a first-class architecture concern
- Be explicit in migration docs that this change reduces repo-owned Java plumbing but does not guarantee zero Java usage in every upstream execution path

### CLI, Action, and migration UX

- Add a read-only CLI command: `node-minify doctor`
- `doctor` should scan:
  - `package.json`
  - source imports in common JS/TS files
  - `.github/workflows/*.yml` and `*.yaml`
- `doctor` should detect and report:
  - removed packages
  - removed built-in compressor names
  - legacy compressor usage
  - deprecated type alias usage
  - Java-sensitive GCC/YUI usage where migration guidance is useful
- Exit behavior:
  - `0` when no issues are found
  - non-zero when removed v11 blockers are found
  - `0` with warnings only for legacy-tier findings
- CLI and GitHub Action should fail early for removed compressor names with direct replacements
- CLI help, action docs, and website docs should show support tier labels rather than a flat list

### Internal implementation changes

- Create one shared compressor-status registry used by CLI, Action, docs helpers, and `doctor`
- Registry should encode:
  - compressor name
  - status: `recommended | supported | legacy | removed`
  - replacement guidance
  - optional notes such as `runtime caveat` for GCC
- Remove v11-removed compressors from built-in lists, examples, docs nav, and tests
- Add one dedicated v11 migration guide covering:
  - removed compressors
  - type alias removals
  - support tiers
  - GCC backend/runtime change
  - preferred replacements by asset type
- Add CI checks preventing removed compressors from appearing outside migration content

## Test Plan

- Unit tests for the compressor-status registry and replacement mappings
- CLI tests for `node-minify doctor`:
  - clean project
  - removed dependency in `package.json`
  - removed import in source
  - removed compressor in workflow/action config
  - legacy-tier warning
  - GCC runtime-guidance messaging
- CLI and Action tests ensuring removed compressors fail clearly
- GCC package tests covering the new backend integration and error handling
- Verification that `@node-minify/run` is no longer referenced anywhere if removed
- Type-level validation that `CompressorReturnType` and `MinifyOptions` are no longer exported
- Repo-wide verification with `bun run ci`

## Assumptions and Defaults

- v11 remains under `@node-minify/*`; the `@mnfy` rebrand is deferred
- v11 remains primarily a cleanup/hardening release with one DX addition: `node-minify doctor`
- `jsonminify` is not removed in v11; it is explicitly downgraded to `Legacy`
- `clean-css`, `csso`, and `uglify-js` remain supported and are de-emphasized rather than removed
- `google-closure-compiler` stays in v11, but its implementation should move away from the repo's custom Java wrapper
- "Replace GCC by its JavaScript version" is interpreted as switching to the main maintained npm package backend, not as a guarantee of a fully pure-JS runtime with no Java fallback
- If the GCC refactor leaves no consumers of `@node-minify/run`, that package should be removed in v11
