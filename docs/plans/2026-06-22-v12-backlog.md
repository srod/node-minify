# v12 Backlog

Items deliberately deferred out of the v11 cleanup release (`docs/plans/2026-03-14-v11-plan.md`). None of these block v11. Captured here so the deferrals don't rot into "later means never".

Status as of 2026-06-22 (v11 branch `v11-cleanup`, ready to merge).

---

## 1. Finish `node-minify doctor` scanners (v11 spec gap)

**What**: The v11 plan (`docs/plans/2026-03-14-v11-plan.md` lines 70–71) specced two `doctor` detections that were not implemented:

- **Deprecated type-alias usage** — flag source importing/using `CompressorReturnType` (→ `CompressorResult`) or `MinifyOptions` (→ `Settings`).
- **Java/GCC runtime guidance** — surface a note when a project uses `google-closure-compiler`, pointing at the runtime caveat (Java may still be invoked upstream) and recommended JS-native alternatives.

**Why deferred**: `doctor` already detects the real migration blockers (removed packages in `package.json`, source imports, workflow YAML) plus legacy-tier warnings. The two missing scanners are migration *nice-to-haves*, not blockers.

**Where**: `packages/cli/src/doctor.ts` (add two scanners + reporter cases), `packages/cli/__tests__/doctor.test.ts` (clean/dirty cases for each). Registry already carries the GCC `runtime caveat` note via `notes` in `packages/utils/src/compressor-registry.ts`.

**Effort**: Small. Mirrors the existing removed-package scanner pattern.

## 2. Deprecate `buildArgs` / `toBuildArgsOptions`

**What**: Mark both as deprecated, then remove in a later major.

**Why deferred**: They are public API exported from `@node-minify/utils`, so that removal is itself a breaking change and belongs on its own deprecation cycle (v11 plan guardrail: "No removal of `buildArgs`/`toBuildArgsOptions` from utils").

**Now dead**: After the GCC JS-API refactor, `google-closure-compiler` was the last real consumer. Confirmed: the only remaining references are the utils barrel export (`packages/utils/src/index.ts`) and their own tests. No package imports them.

**Where**: `packages/utils/src/buildArgs.ts`, `packages/utils/src/index.ts`. Add `@deprecated` JSDoc + a `warnDeprecation()` call in v12, schedule removal for v13.

**Effort**: Small.

---

## 3. Unify `AVAILABLE_MINIFIER` and `KNOWN_COMPRESSOR_EXPORTS`

**What**: Collapse the two parallel compressor lists into one source of truth, ideally derived from the v11 `COMPRESSOR_REGISTRY`.

**Why deferred**: v11 added the registry additively to avoid churn; unification is a refactor with no user-facing payoff for v11 (plan guardrail: "No unification of AVAILABLE_MINIFIER + KNOWN_COMPRESSOR_EXPORTS — additive registry only, v12 concern").

**Where**: `packages/cli/src/config.ts` (`AVAILABLE_MINIFIER`), `packages/cli/src/index.ts`, `packages/utils/src/compressor-resolver.ts` (`KNOWN_COMPRESSOR_EXPORTS`). Target: drive both from `packages/utils/src/compressor-registry.ts`.

**Effort**: Medium. Touches resolver + CLI; needs test coverage for resolution parity.

## 5. Reassess legacy / supported tiers for removal

**What**: Decide whether any de-emphasized compressor graduates to removal in v12.

**Candidates** (kept intentionally in v11):
- `legacy`: `jsonminify`, `no-compress`
- `supported` (not recommended): `clean-css`, `csso`, `uglify-js`, `google-closure-compiler`, `imagemin`, `html-minifier`

**Why deferred**: v11 only downgrades these; removal is a separate decision. `no-compress` is load-bearing (passthrough for concatenation/unknown types) and likely stays. `jsonminify` and the older CSS/JS minifiers are the realistic removal candidates if usage data supports it.

**Where**: `packages/utils/src/compressor-registry.ts` plus the same removal plumbing v11 used (CLI/Action fail-fast, docs, CI guard).

**Effort**: Per-package, same shape as the v11 removals.

## 6. Broaden the removed-compressor CI guard

**What**: Extend `scripts/ci-guard-removed-compressors.sh` to also catch bare compressor identifiers (e.g. `compressor: yui` in a workflow), not just scoped `@node-minify/<name>` package refs, and widen the scan beyond `packages/` + `examples/` to root files and `.github/`.

**Why deferred**: Raised in v11 PR review (CodeRabbit). The current scoped-name guard covers the real import vector. Bare names are false-positive magnets — `run`, `yui`, `crass` appear as substrings in unrelated code/text — so this needs a careful per-name word-boundary pattern (and probably an allowlist) rather than a quick widening. Not worth the FP risk under v11 time pressure.

**Where**: `scripts/ci-guard-removed-compressors.sh`. Match the 5 removed compressor names (not `run`) with word boundaries, scoped to workflow/config files where a bare `compressor:` value can appear.

**Effort**: Small–medium (the FP-avoidance is the work).

---

## 7. Clean up benchmark warmup temp files on failure

**What**: When `minify()` throws mid-loop in `runWarmup` (`packages/benchmark/src/runner.ts`), the already-created warmup files for that run are never deleted — the function returns the path list only on success, so the caller's cleanup can't see partial output.

**Why deferred**: Raised in v11 PR review (cubic). Dev-only benchmark tooling writing temp files; tangential to the v11 compressor cleanup. Fix with a `try/finally` that hands the partial path list to `cleanupTempFiles` even on throw.

**Where**: `packages/benchmark/src/runner.ts` (`runWarmup` + its caller), reuse existing `cleanupTempFiles`.

**Effort**: Small.
