# v12 Backlog

Items deliberately deferred out of the v11 cleanup release (`docs/plans/2026-03-14-v11-plan.md`). None of these block v11. Captured here so the deferrals don't rot into "later means never".

Status as of 2026-09-02: v11.0.0 is published to npm and tagged. Items below are the remaining deferrals, re-checked against the shipped code.

---

## 1. Add GCC runtime guidance to `node-minify doctor`

**Shipped in v11, no longer deferred**: deprecated type-alias detection. `doctor` flags `CompressorReturnType` (→ `CompressorResult`) and `MinifyOptions` (→ `Settings`) in TypeScript imports and re-exports, ignoring comments and template literals. It also gained detection for the removed `@node-minify/run` package and for `engines.node` ranges that still allow Node below 22.

**Still outstanding**:

- **Java/GCC runtime guidance** — surface a note when a project uses `google-closure-compiler`, pointing at the runtime caveat (Java may still be invoked upstream) and recommended JS-native alternatives.

**Why deferred**: `doctor` already detects every v11 breaking change. This is migration polish, not a blocker.

**Where**: `packages/cli/src/doctor.ts` (add one scanner + reporter case), `packages/cli/__tests__/doctor.test.ts` (clean/dirty cases). Note: `CompressorEntry` in `packages/utils/src/compressor-registry.ts` has only `name`, `status`, `packageName` and optional `replacement` — there is **no** `notes` field, so the caveat text needs adding along with the scanner.

**Effort**: Small. Mirrors the existing removed-package scanner pattern.

## 2. Deprecate `buildArgs` / `toBuildArgsOptions`

**What**: Mark both as deprecated, then remove in a later major.

**Why deferred**: They are public API exported from `@node-minify/utils`, so that removal is itself a breaking change and belongs on its own deprecation cycle (v11 plan guardrail: "No removal of `buildArgs`/`toBuildArgsOptions` from utils").

**Now dead**: After the GCC JS-API refactor, `google-closure-compiler` was the last real consumer. Confirmed: the only remaining references are the utils barrel export (`packages/utils/src/index.ts`) and their own tests. No package imports them.

**Where**: `packages/utils/src/buildArgs.ts`, `packages/utils/src/index.ts`. Add `@deprecated` JSDoc + a `warnDeprecation()` call in v12, schedule removal for v13.

**Effort**: Small.

## 3. Unify `AVAILABLE_MINIFIER` and `KNOWN_COMPRESSOR_EXPORTS`

**What**: Collapse the two parallel compressor lists into one source of truth, ideally derived from the v11 `COMPRESSOR_REGISTRY`.

**Why deferred**: v11 added the registry additively to avoid churn; unification is a refactor with no user-facing payoff for v11 (plan guardrail: "No unification of AVAILABLE_MINIFIER + KNOWN_COMPRESSOR_EXPORTS — additive registry only, v12 concern").

**Where**: `packages/cli/src/config.ts` (`AVAILABLE_MINIFIER`), `packages/cli/src/index.ts`, `packages/utils/src/compressor-resolver.ts` (`KNOWN_COMPRESSOR_EXPORTS`). Target: drive both from `packages/utils/src/compressor-registry.ts`.

**Effort**: Medium. Touches resolver + CLI; needs test coverage for resolution parity.

## 5. Reassess legacy / supported tiers for removal

**What**: Decide whether any de-emphasized compressor graduates to removal in v12.

**Candidates** (kept intentionally in v11):
- `legacy`: `jsonminify`, `no-compress`
- `supported` (not recommended): `clean-css`, `csso`, `uglify-js`, `google-closure-compiler`, `imagemin`, `html-minifier`

**Why deferred**: v11 only downgrades these; removal is a separate decision. `no-compress` is load-bearing (passthrough for concatenation/unknown types) and likely stays. `jsonminify` and the older CSS/JS minifiers are the realistic removal candidates if usage data supports it.

**Where**: `packages/utils/src/compressor-registry.ts` plus the same removal plumbing v11 used (CLI/Action fail-fast, docs, CI guard).

**Effort**: Per-package, same shape as the v11 removals.

## 6. Refresh or retire the root `Migrate.md`

**What**: Root `Migrate.md` is an older migration guide whose "before" examples still import removed packages (`@node-minify/yui`, `@node-minify/babel-minify`, etc.) and reference `yui-js` / `yui-css`. It is excluded from the CI guard as migration content, so it won't fail CI, but it can mislead v11 readers.

**Why deferred**: Pre-existing doc, not part of the v11 cleanup diff; the canonical v11 path is now `docs/.../guides/v11-migration.md`. Decide whether to fold the still-relevant parts into the v11 guide and delete `Migrate.md`, or update its examples.

**Where**: `Migrate.md`.

**Effort**: Small.

## Post-release ops (not code — track separately)

Status checked against the registry on 2026-09-02, after v11.0.0 published.

- **Done**: the 5 removed compressors are already deprecated on npm — `@node-minify/babel-minify`, `@node-minify/uglify-es`, `@node-minify/yui`, `@node-minify/sqwish`, `@node-minify/crass`. Each message names its replacement.
- **Outstanding**: `@node-minify/run` is removed in v11 but **not** deprecated on npm, so it still installs silently at `10.5.0`. Deprecate it with:

  ```bash
  npm deprecate @node-minify/run "@node-minify/run was removed in v11. It was an internal Java/process-spawn helper with no public replacement; remove it from your dependencies."
  ```

- **Release tagging**: `GITHUB_TOKEN` cannot create a tag whose tree adds `.github/workflows/*`, so the major tag (`v11`) had to be pushed manually. Every future major hits this. Fix with a fine-grained PAT (contents + workflows write) stored as a secret, or by excluding workflow files from the tagged tree.
- **Publish failures are non-fatal**: `scripts/publish.ts` logs `npm publish` and `changeset tag` errors as "may already exist" but still exits 0, so CI cannot distinguish a real failure from a no-op. Until that is fixed, verify published versions against the registry rather than trusting a green Publish run.
